## Findings and fixes

| Priority | Confirmed defect | Correction and evidence |
| --- | --- | --- |
| P1 | Parameter import treated an apostrophe inside a SQL comment as a string delimiter. In nested UNION/APPLY queries, a later real parameter could retain another branch's name and silently bind its value. Actual SQL returned `1,2,2` instead of `1,2,3`, and child IDs `2,2` instead of `2,3`. | Rename code segments separately while preserving line/block/nested comments, quoted strings and identifiers. The same compiled regression consumer went from seven failures/three passes to ten passes after replacing only EasyDapper.dll. |
| P2 | Standalone UNION/UNION ALL/INTERSECT/EXCEPT with ordered operands generated SQL Server syntax errors, including operands using TOP. | Render the combined result through the existing derived-source path when its operands require it. Eight operator/TOP combinations failed before correction and now match independent direct-SQL controls. |
| P2 | An ORDER BY ending in `-- comment` without a newline could consume appended OFFSET, closing parentheses or aliases when embedded in SET/APPLY. | Add a line boundary before embedding that SQL. All four line-comment/SET/APPLY cases failed before correction and now pass. A quoted marker may receive harmless trailing whitespace; its literal contents are preserved. |

Production changes are confined to
[QueryBuilderCore.cs](EasyDapper/QueryBuilding/QueryBuilderCore.cs). Regression cases
are in [SqlParameterLexingRegressionTests.cs](EasyDapper.Tests/QueryBuilder/SqlParameterLexingRegressionTests.cs).
Connection ownership, operation admission, transaction management, parameter
checkpoint journals and captured-field evaluation were not changed in this pass.
